# Claude instructions for this repo

Read `README.md` before making non-trivial changes — it explains the architecture, naming vocabulary, and generated-data boundaries this project depends on. Read `STYLE.md` before writing or refactoring TypeScript — code-shape rules (classes over function modules, getters over returned state bags, dead-code deletion) distilled from the user's own refactors of AI-generated code. The short version:

- **`src/00_*`–`06_API/` are a generic Sheets+Apps-Script framework; `src/businessEndpoints.ts`/`src/businessEndpointHandlers/` are the only place real-estate-specific logic belongs.** Dependencies only point downward by folder number — never import from a higher-numbered tier. `businessEndpoints.ts`/`businessEndpointHandlers/` sit outside the numbering (like `utils/`) and may import from any tier.
- **`02_SpreadsheetRaw`'s classes are raw-index Sheets API access only** — whole rows/columns by GID + index, sheet properties, and `UniformRowRaw`. They never resolve a column by name or `columnId`; that's `03_SpreadsheetIndexed`/`04_SpreadsheetNamed`'s job. The folder also holds `SpreadsheetSchema.ts` (next bullet), which does resolve columns — it lives there because it must sit below both tiers that use it, and Raw classes are limited to `SpreadsheetSchema` by convention, not by the import graph. Generating/updating `01_generatedConfigs` is a separate `05_Operators` tier's job (`SheetConfigOperator`/`ColumnConfigOperator`/`ValueConfigOperator`, coordinated by `ConfigOrchestrator`) — config maintenance is neither Raw's nor Named's responsibility.
- **Three schema classes, one accessor.** `SpreadsheetSchema`/`SheetSchema`/`ColumnSchema` all live in `src/02_SpreadsheetRaw/SpreadsheetSchema.ts` — one module, because they form an import cycle that would crash at Apps Script runtime if split. Every class that has a schema exposes it as `schema`, narrowed to its level (spreadsheet, sheet/row, or column/cell); `baseSchema`/`ssSchema`/`columnSchema`/`sheetSchema` are gone. Build one via `SheetSchema.fromSheetName`/`.fromSheetGid` or `ColumnSchema.fromColumnName`/`.fromColumnId` — name-addressed gets full literal precision, GID-addressed gets the widened default. `SheetSchema` and `ColumnSchema` are siblings, not parent and child. See README's "The schema classes".
- **Never run `clasp push`, `clasp run`, `clasp deploy`, `npm run build`, or `npm run gen:configs` without asking first.** They affect a live Apps Script deployment. `npm run gen:configs` doesn't just read — it writes to the live Sheet Config/Column Config sheets and to business sheets' header rows (missing column IDs), then atomically regenerates `sheetConfigs.ts`/`columnConfigs.ts`/`valueConfigs.ts` together, all three or none. Never run a partial/older regeneration path that updates a subset instead — see README.md's "Generated data" section for why. `npm run tsc` is always safe.
- **The `gsheets` MCP's read tools (`list_spreadsheets`, `list_sheets`, `get_sheet_data`) are always fine.** Any write tool (`create_spreadsheet`, `create_sheet`, `update_cells`, `batch_update_cells`) needs a stated specific plan — exact sheet/range/values, or exact new sheet/spreadsheet — and explicit permission first, not a general go-ahead. `share_spreadsheet` needs its own separate confirmation of exactly who and at what permission level, since it grants access rather than just changing data.
- **Don't hand-edit the generated data** in `sheetConfigs`/`columnConfigs`/`valueConfigs` (`src/01_generatedConfigs/`) — regenerate from the spreadsheet instead, per README. Exception: `sheetConfigs`/`columnConfigs` entries for the config-describing sheets themselves (`sheetConfig`, `columnConfig`, `spreadsheetConfig`, `valueConfig`) form a guaranteed floor and are meant to stay fixed rather than be regenerated away (see README).
- **An action-checkbox column's *name suffix* decides how its endpoint runs**, per the suffixes declared in `spreadsheetConfig`: `...TimeLastRan` is a **runner** (a run button — fires only on check), `...Select` is a **selector** (the checkbox is the input — fires on check *and* uncheck, and receives the value). Register endpoints with a plain `: Endpoints` annotation, never `makeStructuredConfig`, which silently accepts a key that isn't a real column. See README's "Endpoint dispatch".
- **Optimizing a trigger means removing a Sheets round trip — nothing else moves the number.** All API traffic funnels through `SpreadsheetRaw.fetchAllGathered`/`_sendUpdateRequests` (~250–450ms each); the framework's own CPU is ~20–60ms per run. `SpreadsheetApp` was measured as a cheaper alternative and is *slower*; don't re-propose it without new measurements. See README's "Round trips are the cost".
- **This code runs in Google Apps Script, not Node.** No Node/DOM APIs at runtime — only in build tooling.
- **Tests run on Vitest, safe to run freely.** `npm test` (or `npm run test:coverage`) never touches the live spreadsheet or Apps Script — everything it exercises runs against fakes. Co-locate a new test as `Foo.test.ts` next to `Foo.ts`; shared fakes for the ambient GAS globals (`Sheets`, `PropertiesService`, `ScriptApp`, `SpreadsheetApp`) live in `src/testSupport/`, outside the tier numbering like `utils/`. See README's "Testing" section for the mocking approach and what's covered so far. `npm run tsc` remains the whole *type*-verification story; run both before calling a change done.
- `src/businessEndpoints.ts` is live (wired into `triggerOnEdit` via `06_API`'s `Api` class), but the domain classes it will eventually call (`ChargeMgmt`, `ExpenseMgmt`, `LeaseMgmt`, `LedgerMgmt`, `PaymentMgmt`, `SubsidyMgmt`, in `src/businessEndpointHandlers/`) are still fully commented out, pre-reorg legacy awaiting reimplementation. None of this is broken — an expected state, and STYLE.md's commented-out-code exception applies here: ask before deleting or rewriting over these blocks.

The naming words **Raw / Indexed / Named / Operator / Trait / Config / Schema / Selector / Runner** are used precisely (defined in README.md). If you're placing or renaming a file and unsure which applies, ask rather than guess.
